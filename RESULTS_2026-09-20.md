# Real results — Colab run, 2026-09-20 (perceptual check closes the gap)

This run followed a full Colab runtime restart + "Run all" (forced by the
`load_hardened_pool` / `KeyError: 'ssim_pass'` bugfixes), so Stages 8.3
through 8.6 were re-executed end-to-end from scratch — an independent
second run, not a resume of 2026-09-19's session state. The new Section
6.5 also ran successfully for the first time, closing the gap flagged in
`RESULTS_2026-09-19.md`.

## Headline finding: the perceptual check fails

```
Checking Stage 8.5 (CNN-only hardened) crops...
Stage 8.5 (CNN-only): 1058 crops checked, SSIM pass rate = 15.8% (mean SSIM 0.8521, worst 0.5398)
  LPIPS pass rate = 47.5% (mean 0.1203, worst 0.3560)

Checking Stage 8.4 (dual hardened) crops...
Stage 8.4 (dual): 1058 crops checked, SSIM pass rate = 15.7% (mean SSIM 0.8527, worst 0.5393)
  LPIPS pass rate = 47.6% (mean 0.1214, worst 0.3761)
```

**Only about 1 in 6 hardened crops pass the SSIM ≥ 0.90 "looks unchanged
to a human" threshold**, for both hardening variants. Mean SSIM (~0.852)
sits well below the 0.90 bar, and the worst cases (~0.54) are far below
it. LPIPS is somewhat more forgiving (~47.5% pass) but still means most
crops fail even the more perceptually-tuned metric.

**What this means:** `PGD_EPSILON = 8/255` is too large for this
application. At that budget, PGD is finding perturbations that fool the
CNN/CLIP classifiers, but the majority of the time it's doing so by
visibly distorting the image — not through an imperceptible, human-
invisible nudge. This directly undermines the CAPTCHA's core requirement
("hard for bots, easy for humans"): a CAPTCHA that a human can also
struggle to read is not a working CAPTCHA, whatever its solve-rate
numbers against bots look like.

**This is the single most important actionable finding from Stages
8.3–8.6 so far**, and it changes how every number below should be read.

## Run-to-run comparison (2026-09-19 vs. 2026-09-20)

| image_set | attacker | run 1 (09-19) | run 2 (09-20) |
|---|---|---|---|
| original | held-out | 0.733 | 0.767 |
| cnn_only_hardened | CLIP | 0.683 | 0.683 |
| cnn_only_hardened | held-out | 0.267 | 0.317 |
| dual_hardened | CLIP | 0.600 | 0.500 |
| dual_hardened | held-out | 0.350 | 0.383 |

Two independent end-to-end runs (different random crop/PGD initial
conditions, since Colab's runtime state was fully reset between them) now
exist, which lets the two findings from run 1 be checked for consistency
rather than trusted off a single run:

1. **Novelty claim (dual beats CNN-only against CLIP): holds in both
   runs.** Dual hardening's CLIP solve rate is lower than CNN-only's in
   both run 1 (0.600 vs 0.683) and run 2 (0.500 vs 0.683) — if anything
   the effect is *larger* in run 2. This is now supported by two
   independent runs, not one.
2. **Held-out contradiction (dual transfers worse than CNN-only to the
   untrained ResNet18): also holds in both runs.** Dual's held-out solve
   rate is higher (worse defended) than CNN-only's in both run 1 (0.350
   vs 0.267) and run 2 (0.383 vs 0.317). This is the "opposite of what
   dual-defense-generalizes-better would predict" pattern from run 1,
   and it reproduces.
3. **Ensemble column is still uninformative** in run 2 too (0.000 for
   both hardened sets, identical to the CNN column) — same root cause as
   run 1 (CNN's confidence collapse dominates the 50/50 vote).

So: the two most important qualitative patterns from Stage 8.6 are now
each confirmed across two independent runs, which is meaningfully
stronger evidence than either run alone. But both runs were computed at
the same `PGD_EPSILON=8/255` that Section 6.5 just showed produces mostly
visible corruption — so while the *relative* comparisons (dual vs.
CNN-only) look robust, the *absolute* solve-rate numbers in this table
should not yet be treated as representing a usable, imperceptible
CAPTCHA hardening. They're informative about how the PGD mechanism
behaves, not yet a result ready for the paper.

## What to do next (in order)

1. **Lower `PGD_EPSILON`** from 8/255 to something like 2/255 or 1/255,
   and re-run Sections 6.3 through 7.5. Re-check the Section 6.5 SSIM/LPIPS
   pass rate after each attempt — the goal is a high pass rate (e.g. >90%)
   before trusting any solve-rate number as a final result.
2. Once epsilon is tuned, re-check whether the two Stage 8.6 patterns
   above (CLIP-column novelty support, held-out contradiction) still hold
   at the new, perceptually-valid budget — they were both established at
   an epsilon we now know is too large, so they need re-confirming, not
   assumed to carry over.
3. Redesign the Ensemble voting scheme (weight CLIP more heavily, or
   require both attackers to agree) so it stops just echoing the CNN
   column.
4. Only after 1–2 above produce a perceptually-valid hardening: treat the
   matrix as ready for Stage 8.8's consolidation and 8.9's write-up.
